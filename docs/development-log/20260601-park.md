# Project Status and Invitation Feature

## Summary

프로젝트 정보 기능에 프로젝트 상태 관리와 초대 기반 팀원 추가 흐름을 구현했다.

이번 작업의 핵심은 다음 세 가지다.

1. 프로젝트 상태를 `진행중`, `완료`, `중단`으로 관리한다.
2. 완료 또는 중단된 프로젝트는 조회만 가능하게 하고, 수정 작업을 서비스 계층에서 차단한다.
3. 팀원 추가를 즉시 추가 방식이 아니라 `ProjectInvitation` 기반의 초대/수락 방식으로 통일한다.

추가로 팀원이 만든 공통 사이드바 레이아웃을 주요 화면에 적용했고, 테스트 환경을 H2 DB로 분리해 VM MySQL 실행 여부와 무관하게 `mvn test`를 실행할 수 있게 했다.

## Project Status

프로젝트 상태는 enum으로 저장한다.

| Enum | Label | CSS class |
| --- | --- | --- |
| `IN_PROGRESS` | 진행중 | `in-progress` |
| `COMPLETED` | 완료 | `completed` |
| `PAUSED` | 중단 | `paused` |

새 프로젝트의 기본 상태는 `IN_PROGRESS`다.

```java
@Enumerated(EnumType.STRING)
@Column(nullable = false, length = 20)
private ProjectStatus status = ProjectStatus.IN_PROGRESS;
```

상태 변경은 프로젝트 오너만 가능하다.

```java
public void updateProjectStatus(String email, Long projectId, ProjectStatus status)
```

상태 전환은 모든 방향으로 허용한다.

- 진행중 -> 완료
- 진행중 -> 중단
- 완료 -> 진행중
- 완료 -> 중단
- 중단 -> 진행중
- 중단 -> 완료

## Edit Lock Policy

`IN_PROGRESS` 상태에서는 기존 수정 기능을 사용할 수 있다.

`COMPLETED`, `PAUSED` 상태에서는 프로젝트를 조회만 할 수 있다. 단, 오너는 상태 변경과 프로젝트 삭제를 계속 할 수 있다.

서비스 계층에서 다음 공통 검증으로 수정 작업을 차단한다.

```java
private void assertProjectEditable(Project project) {
    if (project.getStatus() != ProjectStatus.IN_PROGRESS) {
        throw new IllegalArgumentException("완료 또는 중단된 프로젝트는 수정할 수 없습니다.");
    }
}
```

완료/중단 상태에서 차단되는 작업은 다음과 같다.

- 작업 링크 추가
- 초대 보내기
- 이메일 초대 보내기
- 태스크 추가
- 태스크 완료 토글
- 초대 수락

상태 변경과 프로젝트 삭제에는 `assertProjectEditable`을 적용하지 않는다.

## Project Deletion

프로젝트 삭제는 완전 삭제로 유지한다.

- 오너만 삭제할 수 있다.
- 프로젝트가 진행중, 완료, 중단 중 어떤 상태여도 삭제할 수 있다.
- 삭제 시 연관 데이터를 먼저 삭제한 뒤 프로젝트를 삭제한다.

삭제 순서:

1. `ProjectInvitation`
2. `ProjectTask`
3. `ProjectLink`
4. `ProjectMember`
5. `Project`

## Completion Warning

프로젝트를 `COMPLETED`로 변경할 때 미완료 태스크가 있어도 완료 자체는 허용한다.

대신 화면에서 confirm 경고를 보여준다.

```text
미완료 태스크가 있습니다. 그래도 완료하시겠습니까?
```

서버는 미완료 태스크를 이유로 완료 상태 변경을 차단하지 않는다.

## Invitation Flow

팀원 추가는 `ProjectInvitation` 기반으로 통일했다.

기존처럼 이메일을 입력하거나 후보 목록에서 사용자를 선택해도 즉시 `ProjectMember`를 만들지 않는다. 두 방식 모두 `ProjectInvitation(PENDING)`을 생성하고, 초대받은 사용자가 수락해야 프로젝트 멤버가 된다.

지원하는 초대 방식:

- 추천 후보 목록에서 초대
- 이메일 직접 입력으로 초대

공통 정책:

- 오너만 초대할 수 있다.
- 진행중 프로젝트에서만 초대할 수 있다.
- 이미 프로젝트 멤버인 사용자는 초대할 수 없다.
- 이미 대기 중인 초대가 있으면 다시 초대할 수 없다.
- 자기 자신에게는 초대할 수 없다.
- 가입되지 않은 이메일은 초대할 수 없다.

주요 메서드:

```java
public void sendInvitation(String email, Long projectId, Long receiverId)

public void sendInvitationByEmail(String senderEmail, Long projectId, String receiverEmail)

private void createInvitation(Project project, Member sender, Member receiver)

private ProjectMember addProjectMember(Project project, Member member)
```

초대 수락 시에만 `ProjectMember`가 생성된다.

```java
public Project acceptInvitation(String email, Long invitationId)
```

초대 거절은 초대 상태만 `REJECTED`로 바꾼다.

```java
public void rejectInvitation(String email, Long invitationId)
```

- 태스크 추가 form
- 태스크 완료 체크박스

- 팀원 추가 버튼

- 태스크 추가 form
- 태스크 완료 토글 form

### Task List

태스크 목록은 미완료 태스크를 위에 보여주고, 완료 태스크는 아래에 보여준다.

완료 태스크는 체크박스가 체크되고, 텍스트에 취소선을 표시한다.

상태별 필터는 이번 범위에 포함하지 않았다.

### Invitations

초대 목록 화면에서 다음 정보를 보여준다.

- 프로젝트 이름
- 프로젝트 상태 배지
- 프로젝트 설명
- 초대한 사람 이름/이메일
- 수락 버튼
- 거절 버튼
- 상세 보기 버튼

완료/중단 프로젝트 초대는 목록과 상세 화면에서 수락 버튼을 숨긴다.

초대 수락 성공 시 프로젝트 상세로 이동하며 flash 메시지를 보여준다.

```text
프로젝트에 참여했습니다.
```

초대 거절 성공 시 초대 목록으로 이동하며 flash 메시지를 보여준다.

```text
초대를 거절했습니다.
```

### Sidebar

팀원이 만든 공통 사이드바를 주요 로그인 화면에 적용했다.

적용 화면:

- 홈 대시보드
- 프로젝트 상세
- 초대 목록
- 초대 상세
- 프로필

로그인/회원가입 화면은 독립 인증 화면으로 유지했다.

사이드바에 필요한 공통 모델은 `SidebarModelAdvice`에서 제공한다.

- `sidebarMemberName`
- `sidebarProjects`

## Test Coverage

- 프로젝트 생성 시 기본 상태가 `IN_PROGRESS`

- 같은 상태로 변경해도 에러 없음

- 중단 상태에서 링크 추가 불가

- 완료 상태에서도 오너는 프로젝트 삭제 가능
- 이메일 초대는 오너만 가능
